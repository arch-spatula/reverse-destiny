# 시작 화면

## 목적과 범위

참여 인원을 선택하고 방 만들기를 요청하는 화면이다. 방 생성 결과로 입장용 QR을 표시한다.

## 화면 구성

위에서 아래 순서로 배치한다.

1. 인원 선택 stepper: `−` 버튼, 현재 인원, `+` 버튼
2. `방 만들기` 버튼
3. 방 생성 결과를 표시하는 QR 영역: 요청 전에는 표시하지 않는다.

## 사용자 흐름

1. 시작 화면에서 참여 인원을 선택한다.
2. `방 만들기` 버튼을 누른다.
3. 선택한 인원으로 방 생성을 요청한다.
4. 성공 응답을 받으면 화면의 QR 영역에 입장용 QR을 표시한다.

## 요구사항

### 인원 선택

- [게임 룰](game-rules.md)에 따라 4~6명 중 선택한다.
- 초기 기본값은 4명으로 둔다.
- `−`와 `+`를 누르면 인원이 1명씩 감소하거나 증가한다.
- 4명일 때 `−`, 6명일 때 `+` 버튼을 비활성화한다.
- 인원 선택 stepper는 `방 만들기` 버튼 위에 둔다.

### 방 만들기와 QR 응답

- 화면 진입만으로 방을 생성하지 않는다. `방 만들기` 버튼을 눌렀을 때 요청한다.
- 요청에 현재 선택한 인원을 포함한다.
- 방 생성 성공 응답에 따라 QR을 표시한다.
- 초기 구현에서는 실제 서버 요청과 QR 생성 대신 모의 응답을 사용하고, QR 영역을 `<div>QR임</div>`으로 표시해도 된다.
- 임시 표시는 실제로 스캔할 수 있는 QR이나 방 입장을 구현한 것으로 간주하지 않는다.
- 실제 QR 입장 흐름은 [방 만들기 스펙](room-creation.md)을 따른다.

## 수용 기준

- 시작 화면에서 인원 선택 stepper가 `방 만들기` 버튼 위에 보인다.
- 초기 인원은 4명이며, 버튼으로 4~6명 범위에서 1명씩 변경할 수 있다.
- 방 만들기 요청에는 버튼을 누른 시점에 선택한 인원이 사용된다.
- 요청 전에는 QR 영역이 보이지 않는다.
- 방 만들기 성공 응답 후 QR 영역이 표시된다. 초기 구현에서는 `QR임` 문구 표시로 확인한다.

## 미결정 사항

- 실제 방 생성 API와 응답 형식
- 요청 중·실패 시 화면 처리 및 생성 후 재요청 허용 여부
