# 시작 화면

## 목적과 범위

참여 인원을 선택하고 방 만들기를 요청하는 화면이다. 방 생성 성공 후 별도 방 화면으로 이동해 입장용 QR을 표시한다.

## 화면 구성

위에서 아래 순서로 배치한다.

1. 인원 선택 stepper: `−` 버튼, 현재 인원, `+` 버튼
2. `방 만들기` 버튼
방 생성 결과의 QR 영역은 별도 방 화면(`/rooms/:roomId`)에 표시한다.

## 사용자 흐름

1. 시작 화면에서 참여 인원을 선택한다.
2. `방 만들기` 버튼을 누른다.
3. 선택한 인원으로 방 생성을 요청한다.
4. 성공 응답의 방 ID로 `/rooms/:roomId`에 이동하고 입장용 QR을 표시한다.

## 요구사항

### 인원 선택

- [게임 룰](game-rules.md)에 따라 4~6명 중 선택한다.
- 초기 기본값은 4명으로 둔다.
- `−`와 `+`를 누르면 인원이 1명씩 감소하거나 증가한다.
- 4명일 때 `−`, 6명일 때 `+` 버튼을 비활성화한다.
- 인원 선택 stepper는 `방 만들기` 버튼 위에 둔다.

### 방 만들기와 QR 응답

- 화면 진입만으로 방을 생성하지 않는다. `방 만들기` 버튼을 눌렀을 때 요청한다.
- 요청에 현재 선택한 인원을 포함한다.
- 방 생성 성공 응답의 방 ID로 방 화면에 이동하고 QR을 표시한다.
- QR은 실제로 스캔할 수 있는 형태로 표시한다.
- 방 ID에 개발용 접두어를 붙이지 않는다.
- QR의 목적지와 QR 아래 `입장` 버튼의 새 탭 동작은 [방 입장 스펙](room-entry.md)을 따른다.

## 수용 기준

- 시작 화면에서 인원 선택 stepper가 `방 만들기` 버튼 위에 보인다.
- 초기 인원은 4명이며, 버튼으로 4~6명 범위에서 1명씩 변경할 수 있다.
- 방 만들기 요청에는 버튼을 누른 시점에 선택한 인원이 사용된다.
- 요청 전에는 QR 영역이 보이지 않는다.
- 방 만들기 성공 응답 후 `/rooms/:roomId`로 이동해 실제로 스캔할 수 있는 QR이 표시된다.
- 방 URL을 새로고침하거나 직접 열어도 해당 방 ID의 QR 화면을 표시한다. 실제 방 데이터 복원과 유효성 확인은 API 구현 시 추가한다.

## 현재 구현 상태

- 방 생성 API는 연결되지 않았으며, 브라우저에서 시간값으로 방 ID를 만들어 반환한다. 서버에 방을 저장하거나 유효성을 검증하지 않는다.
- QR 생성은 구현되어 있지만 현재 QR 표시 화면 자체를 가리킨다. 참가 URL 연결과 새 탭 입장 버튼은 [방 입장 스펙](room-entry.md)에 따라 구현해야 한다.
- 위 구현 상태는 완료된 수용 기준을 의미하지 않는다.

## 미결정 사항

- 실제 방 생성 API와 응답 형식
- 요청 중·실패 시 화면 처리 및 생성 후 재요청 허용 여부
