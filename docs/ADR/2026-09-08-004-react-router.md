# 화면 라우팅에 React Router 사용

- 상태: 채택
- 작성일: 2026-09-08

## 배경

방 만들기 성공 후 별도 방 화면으로 이동해야 한다. 휴대폰 브라우저에서 화면을 잠그거나 페이지가 다시 로드되어도 같은 방으로 복귀할 수 있도록 URL에 방 식별자를 보존할 필요가 있다.

## 검토한 대안

- React Router: 참고할 문서와 사용 사례가 많고 선언형 모드로 간단하게 화면 이동을 구현할 수 있다.
- TanStack Router: 경로와 검색 파라미터의 타입 안전성을 활용해 URL 상태를 관리할 수 있다.

## 결정과 이유

- 레퍼런스가 많고 구성이 단순한 React Router의 선언형 모드를 사용한다.
- 기존 React + Vite 구조에 `BrowserRouter`와 `Routes`를 추가한다.
- 시작 화면은 `/`, 방 화면은 `/rooms/:roomId`로 구성한다.
- 방 만들기 성공 응답의 방 ID로 이동하고, 방 화면에 입장용 QR을 표시한다. 초기 구현은 모의 방 ID와 `QR임` 표시를 사용한다.

## 결과 및 트레이드오프

- 모바일 환경에서 상태의 영구 저장과 복원이 중요하다. URL에는 방 ID 등 복원에 필요한 공개 정보를 보존하고, 게임 상태의 영구 저장은 서버 저장소에서 처리한다.
- 향후 URL에 보존할 상태가 늘어나 검색 파라미터의 검증과 타입 안전성이 중요해지면 TanStack Router로 전환하는 것도 고려한다. React Router에서도 URL 상태 보존은 가능하며, 전환 자체가 영구 저장을 보장하지는 않는다.
- 개인 정보와 세션 토큰은 URL에 넣지 않는다.
- 현재는 화면 이동만 구현한다. 모의 방 데이터와 선택 인원은 영구 저장하지 않으며, 새로고침 시 URL에 해당하는 QR 임시 화면만 표시한다. 실제 방 조회, 유효성 확인, 세션 및 게임 상태 복원은 API 구현 시 추가한다.
- 배포 시 `/rooms/:roomId` 직접 접근과 새로고침에도 앱을 제공하도록 SPA 경로 처리가 필요하다. `/api` 요청은 별도로 처리해야 한다.
